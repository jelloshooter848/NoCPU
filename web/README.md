# NoCPU Pong browser frontend

The 0.2.0 frontend presents ROM-free Pong from DICE's original-derived C++ circuit engine. It uses TypeScript and Vite, a dedicated WebAssembly worker, a Canvas display, and Web Audio playback of the engine's signed mono PCM. The frontend contains no replacement game rules or synthesized Pong effects. Physical Android/iPhone qualification is tracked separately in [0.2.0 validation](../docs/0.2.0_VALIDATION.md).

`main.ts` owns the player interface and ordered control/input requests. `core.worker.ts` loads the Wasm module from the site's configured base path, preserves picosecond telemetry as a string, copies module-owned video/PCM before transfer, and clears consumed buffers. The worker advances simulation from its own bounded clock; Canvas presentation cadence cannot slow the circuit. Transfers are bounded, and paused or hidden time is discarded rather than replayed as a backlog.

The shell fills the browser viewport. Its title screen offers Play Pong, Settings, How to play and About. Play Pong loads the original attract display; Insert coin starts a game. During play, only the circuit court and compact coin/menu controls remain visible. There is no duplicate frontend score or substitute court. The circuit raster retains its 4:3 aspect ratio; unused space accommodates the browser/device viewport. Fullscreen is not required for play.

Player 1 uses W/S and player 2 uses Up/Down. Transparent touch regions cover the court's left and right halves and each captures one pointer independently; two players can drag at once. Absolute controls cover the full original joystick axis range. Enter inserts a coin; Space or Escape opens the paused menu or explicitly resumes from it. Pointer cancellation, page blur, and pause release buttons and held motion keys while retaining the paddle's last absolute position.

Menu pauses the circuit and offers Resume, Reset game, Settings, How to play, About and Return to title. Settings contains sound and volume. About retains DICE attribution, version/build identification, GPL and component notices, and matching source access. Back from a secondary panel returns to the paused menu or title, never resumes play implicitly. Loading and failure/retry screens stay inside the same shell. Panels may scroll internally; the document and gameplay gestures do not scroll. Physical safe-area spacing and compact portrait/landscape layouts are part of the shell's acceptance checks.

The first player gesture unlocks audio. Playback keeps a short bounded lead, preserves that lead when inserting another coin, and discards old audio on pause/reset/interruption. A backgrounded page requires the player to resume. Device activation has a bounded wait and never prevents simulation from resuming; unavailable sound has an Enable sound retry control. Expired activation attempts cannot resume playback after backgrounding.

Run `npm ci`, `npm run build`, and `npm run preview` from the repository root using the prerequisites in [testing](../docs/TESTING.md). The default URL base is `/NoCPU/`; `NOCPU_BASE_PATH` can configure a different absolute path ending in `/`. The packaged Pages artifact supplies runtime licenses and its matching corresponding-source archive. Build identity and preview/release status are read from the artifact's `BUILD-MANIFEST.json`; unavailable metadata retains the preview label. This lets the tested runtime remain unchanged when promoting a preview to a release.

`?debug` exposes read-only snapshots for automated validation: integer time as a decimal string, circuit scoring/hit state, input ownership, worker timings, and PCM scheduling metrics. `wasmMemoryCapacityBytes` is the allocated Wasm memory capacity, not total browser process memory. `coreOverruns` counts samples the core could not retain. This is validation observability; rendered gameplay always comes from the circuit's output. Read [architecture](../docs/ARCHITECTURE.md) and the [roadmap](../docs/ROADMAP.md) for later library, gamepad, and ROM support.
