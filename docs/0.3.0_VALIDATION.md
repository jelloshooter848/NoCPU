## Physical devices and final release

Keep [release-readiness.json](../tests/release-readiness.json) at preview, false readiness and pending/null actual-device fields until real testing supplies model, OS/browser, test date, full tested build/runtime, all required checks and performance evidence. Use the [phone procedure](0.2.0_VALIDATION.md#physical-phone-evidence), including both external paddle tracks, portrait/landscape reachability and recovery. Record at least 600 seconds of active play with simulation/wall ratio ≥0.95, frame pacing, audio underruns, memory start/end and input response. Actual speaker sound and phone thermal/touch behavior are separate from automation.

The user-authorized app foundation and reviewed preview work can proceed while those fields remain pending. Broad additional-game support and final-tag readiness retain their agreed actual-device decision gate. Changed runtime bytes require matching evidence; successful 0.2.1 feedback cannot be relabeled as a 0.3.0 qualification. Never fabricate device fields, mark individual unreported checks passed or backdate a tag.

For the 0.3.0 app panels, also record manual phone observations of Library →
game information → Help/Settings → Back, focus and reachable internal scrolling
in both orientations. Check changed settings after reload and the visible
recovery path when local storage is unavailable or cleared. Where tested with
the player's own compatible files, record the local file picker, session import,
opt-in Remember, removal and re-import; never publish those files or infer other
gameplay from a successful import. Record supported fullscreen or the usable
normal-tab fallback. These app observations remain pending and supplement the
identified-runtime Pong procedure; they do not waive any physical release gate.
