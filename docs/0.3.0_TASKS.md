## Product result

Keep the title screen’s quick Play Pong action. A full-viewport game application offers library → game information → Play → pause/settings → return to library. The library lists all 21 audited DICE titles with explicit browser availability, source-derived player counts/shared control groups, control information and ROM requirements, without promising validated simultaneous play for future titles. Only Pong launches; importing a ROM never implies that an unavailable browser game can launch. Back follows the originating screen and never silently resumes a paused game. Keep the original 4:3 court, external independent paddle tracks, compact controls, source/About access and no outer document scroll.

Pong gains keyboard/gamepad remapping with independent player ownership and safe disconnect/cancel/menu/background recovery. Shared typed control definitions drive bindings and help, including honest metadata for future titles. Preserve the worker-owned integer simulation clock and circuit PCM; preferences cannot change circuit rules or invent unsupported DIP behavior.

Versioned local preferences retain supported sound, binding and interface choices; storage failures, migration and reset remain recoverable. Optional player-supplied ROM import verifies bounded archive/member data against active audited CRCs and observed byte sizes. Descriptor names are documentary; valid renamed or nested members must pass byte compatibility checks. Retention is opt-in, files can be removed, and unavailable/evicted storage never prevents ROM-free Pong play. No ROM bytes, fixtures or credentials enter the public repository, package or CI artifacts. Fullscreen is optional where supported and requires a usable ordinary-viewport fallback.

## Physical-device and publication boundaries

Keep final release readiness false and actual Android/iPhone fields pending until complete actual-device evidence identifies model, OS/browser, tested build and full runtime digest, all required touch/sound/lifecycle/layout checks, and at least 600 seconds at simulation/wall ratio ≥0.95 with pacing, underruns, memory and input response. The user's two successful 0.2.1 iPhone games and sound feedback are useful partial evidence, not a measured 0.3.0 qualification. Runtime changes require matching qualification. Select and record the supported device floor from actual evidence; no final tag or release is published without the agreed gate.

A source-ready, license-ready or automated browser pass is separate from final phone readiness. Reviewed preview publication is allowed with clearly identified pending phone gates. Publication still requires independent candidate review, mandatory CI, exact artifact/source approval and independent actual-live verification.
