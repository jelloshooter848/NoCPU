## Game-first shell correction

The initial playable preview passed its recorded technical checks but used a
page-style frontend. The user requested the viewport game experience modeled
on SMBC. These scoped 0.2.0 tasks replace that presentation while preserving
the original circuit, worker clock, audio delivery and Pong-only scope.
Earlier runtime evidence remains historical until the revised bytes are
tested; physical Android/iPhone gates remain pending.

| ID | Task | Owner | Required evidence | Status |
| --- | --- | --- | --- | --- |
| G01 | Audit SMBC's final product and define the game-shell contract | Product reviewer | Reference comparison and explicit presentation acceptance | Complete; independent product audit defines viewport game states and compact contextual controls |
| G02 | Implement title, loading, play, paused menu, settings, help, About and recoverable-error flow | Shell author | State/lifecycle review; original worker/audio/core invariants retained | Complete; independent static review and packaged browser checks pass |
| G03 | Fit the original 4:3 court and contextual controls to desktop/phone viewports | Style author | No document overflow; original raster, safe-area spacing and usable controls | Complete; independent visual/reference review and six-viewport browser checks pass |
| G04 | Review presentation and exercise the integrated shell independently | Product, structure and browser reviewers | Visual/reference approval; loading, coin, touch, menus, reset, background and error checks | Complete; local and clean CI 67 passes/three expected CDP skips, no failures/retries; assertion review approved |
| G05 | Update guidance and package the reviewed runtime with matching source/notices | Documentation / release | Accurate interaction docs, clean source/package checks and independently reviewed artifacts | Complete; docs, clean CI/source/package and exact public files independently approved |
| G06 | Deploy the reviewed Pages preview and verify the public game shell | Release / independent reviewers | Successful CI/deployment, live gameplay and exact asset/source verification | Complete; exact-main Pages deployment, 25 live cases and all 83 public files verified |

Layout review covers 320 × 568, 390 × 664, 390 × 844, 844 × 390,
1280 × 720 and 1920 × 1080. The document must not scroll; long game panels
may scroll internally. Title/loading/play/pause/settings/help/About/error remain
game states. The play screen keeps the circuit's own score and raster, with no
mock court or duplicate frontend score. Two simultaneous paddle touches must
retain independent ownership. Attribution, version/build identity, GPL,
component notices and matching source remain accessible through About.

The root orchestrator assigns these substantial workstreams and decides review
outcomes. Agents own investigation, implementation, testing, CI/release work and
repairs; another agent independently reviews completed work. Detailed evidence
stays in ignored build output, and concise reports state completed milestones,
named blockers and the actual running/waiting/completed status.
