# 0.4.0 — First additional DICE circuits

The user authorized proceeding to 0.4.0 after the independently verified
0.3.1 preview. This milestone delivers a reviewed **preview** with three
playable original DICE 0.9 games: **Pong, Pong Doubles and Space Race**. The
other eighteen titles remain in the library as explicitly unported. All 21
original titles remain the 1.0 scope. Neither new title needs an external ROM.

Physical iPhone Safari/Android Chrome and controller evidence remains
pending. The user's decision advances preview development and delivery;
it does not turn automation or historical phone feedback into physical
qualification, approve a final tag, or declare broad-game-support readiness.

## Original behavior to preserve

- Pong retains its original circuit, raster, PCM, independent two paddles,
  coin behavior and outside-court touch controls.
- Pong Doubles adds four independent vertical paddles: player 1 outer left,
  player 2 outer right, player 3 inner left and player 4 inner right. Coin and
  Start are separate switches. One coin before Start selects the original
  two-outer-paddle game; two separate coins before Start select all four
  paddles. Preserve that credit-selected behavior without a substitute mode
  toggle. Winning score has original 11/15 options.
- Space Race adds two independent digital Up/Down sticks, distinct Coin and
  Start, original 1 coin/credit or 1 coin/2 credits settings, and the original
  playtime potentiometer (470–1470 kilohms; default 970 kilohms). Its rocket
  graphics are circuit source, not external ROM assets. Preserve implemented
  analog sound and record inherited timer/sound TODOs separately from port
  regressions.
- Keep all original sources byte-identical. The scheduler, integer time,
  circuit inputs, video timing and PCM generation remain original-derived
  C++; browser code translates access to physical controls.

## Incremental acceptance gates

1. Freeze the typed ABI/worker/game/configuration contract. Unsupported games,
   inputs and settings fail safely; unknown observations remain distinct from
   verified zero. Restore all descriptor/configuration/input state on reset
   and switching. Preserve bounded stepping and frame/PCM ownership.
2. Build and instrument a disposable original DICE reference for both new
   circuits. Cover no-credit/no-start behavior, Coin and Start, Doubles' original
   one-credit/two-player and two-credit/four-player modes, every player
   and input direction, default/alternate settings, active gameplay,
   scoring/end state and implemented PCM. Keep actual instrumentation and
   inherited baseline anomalies visible.
3. Compare original output with portable native, then portable native with
   Wasm using controlled seeded scenarios. Retain Pong regression evidence,
   exact event/integer-time checks, media and geometry checks, reset isolation
   and a mixed Pong → Doubles → Space Race → Pong cycle. Do not widen a
   fidelity threshold merely to pass a port.
4. Launch the exact selected game from the game-first library. Offer all
   original supported players, separate Coin/Start where applicable,
   remapping, current help and settings. Preserve existing preferences and
   optional ROM storage. Four independent Doubles rails and Space Race
   digital controls stay outside the unchanged raster in portrait and
   landscape, with cancellation, simultaneous input and full-range access.
5. Run the complete production-packaged browser matrix across the five
   maintained engine/viewport profiles. Preserve prior Pong, settings,
   ROM/storage, media and qualification regressions; add actual new-game
   lifecycle/gameplay/settings/control/error checks. Independently inspect
   narrow-portrait and compact-landscape screenshots. Viewport automation
   and headless PCM delivery are distinct from physical hardware results.
6. Independently approve actual source, assertions, fidelity, interface,
   compiled dependencies/link members, notices and matching source. The old
   Pong-only browser assessment does not clear this expanded binary. Preserve
   known failed runs and report actual passes, skips, retries and limitations.
7. Commit the accepted source, pass required committed CI, review its actual
   artifacts/results, merge, and run exact-main Pages qualification. Verify
   every public file and hash-keyed core request against the approved
   artifact; run proportionate three-game live smoke checks and independent
   result/phone-layout reviews before claiming publication.
8. Record exact deployed source/runtime identity and actual validation results
   in [0.4.0 validation](0.4.0_VALIDATION.md). Final tags and physical readiness
   remain pending until actual runtime-matched device evidence is supplied.
   The [draft three-game device packet](DEVICE_QUALIFICATION_0.4.md) separates
   each title's settings, input observations and measured scope.
