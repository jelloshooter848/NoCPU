# 0.5.0 — iPhone Home Screen support and the next DICE batch

The user authorized implementation and reviewed preview delivery of 0.5.0
after the independently accepted [0.4.0 preview](0.4.0_VALIDATION.md). The
milestone adds online iPhone Home Screen installation and standalone usability
alongside **Breakout**, selected after independent original-source feasibility
review. The intended local library has four playable circuits: Pong, Pong
Doubles, Space Race and Breakout, with seventeen remaining ports; actual
original sixteen-scenario qualification is accepted; the current portable native/Wasm
batch is independently accepted across all sixteen scenarios and sixty-four
behavioral epochs. Final packaged-browser qualification is
still pending. Stunt Cycle
and Indy 4 remain subsequent evaluation candidates. Preserve all 21 original
titles as the 1.0 scope. The public site still serves the accepted three-game
0.4.0 runtime; source selection does not establish a gameplay/performance pass.

Physical phone/controller qualification remains pending. Development and
reviewed preview delivery are authorized; automation does not establish
installed-iPhone behavior, speaker fidelity, a supported device floor or final
hardware readiness. No final tag is authorized. Offline play is excluded by
default and may enter scope only after a concrete reviewed feasibility decision.

## Required behavior

- Add stable manifest `id: /NoCPU/`, start URL/scope under `/NoCPU/`, standalone display,
  install PNG icons and Apple touch metadata. Retain the icon's preferred SVG
  and reproducible generation recipe in matching source. Do not introduce an
  unsupported maskable-icon or automatic Safari-install claim.
- Keep the game-first title/library/play experience. Put unobtrusive manual
  Safari Add to Home Screen guidance in existing Help/About. Installation
  alone does not promise offline operation.
- Support standalone portrait/landscape safe areas and off-court controls,
  normal gesture audio, background/input release and cold relaunch without a
  fullscreen or orientation-lock prerequisite. Relaunch restores tested
  navigation/preferences; it is not an emulator save-state.
- Preserve versioned preferences and opt-in local ROM validation, storage,
  removal, re-import and export. Recover from denied/evicted storage; do not
  promise Safari/installed-context sharing or permanent retention. Never bundle
  private ROMs or expose local ROM/debug/report payloads in public assets.
- For each selected game, preserve original circuit timing, geometry,
  implemented PCM, controls, player slots, settings, Coin/Start, gameplay and
  reset/switch isolation. Record inherited missing hardware or audio separately
  from regressions. Assets and original comparisons must determine feasibility.

## Acceptance sequence

1. Complete the selected Breakout original asset/control/settings/audio and
   performance evidence. Freeze the typed game/options/input/observation
   interface and original scenarios before implementation claims.
2. Independently review engine and frontend source. Retain immutable original
   source and all existing circuit/settings/storage/qualification regressions.
3. Run original → portable native → Wasm comparisons for the complete selected
   scenario set, plus existing Pong/Doubles/Space Race, reset/mixed-switch and
   ABI/media ownership checks. Preserve exact gates and full compared raw media.
4. Review fresh actual compiled/link-member/frontend inventories, source
   identities and applicable notices. Package only current provenanced outputs
   with matching preferred source; old license evidence does not clear new bytes.
5. Validate the production package across maintained browser profiles,
   including install metadata/base paths, standalone emulation, lifecycle,
   storage errors, controls/settings/media and current title/report identities.
   Independently inspect game-first mobile layouts. Actual identified Safari
   and installed-iPhone checks remain separate and pending until measured.
6. Commit the accepted source, pass ordinary required committed CI, inspect
   its actual source/media/browser artifacts, merge and run one selected
   exact-main Pages preview pipeline. Preserve every failed/superseded attempt.
7. Independently verify public package/source/notices and hash-keyed runtime
   responses, run proportionate live selected-game checks, and record exact
   deployed identity/results. A minimal later outcome-docs commit must not
   relabel or needlessly republish the accepted runtime.
